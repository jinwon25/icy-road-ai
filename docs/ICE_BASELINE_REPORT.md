# 첫 결빙 분류 모델과 실패 분석 — 2026-09-23

기상 자료로 결빙 여부를 직접 분류한 첫 모델의 결과입니다. 결빙을 많이 놓치는 방식과 오경보가 많은 방식의 차이를 비교했으며 둘 다 최종 모델로 채택하지 않았습니다.

[문서 목록·용어 풀이](README.md) · [프로젝트 소개](../README.md)

공식 보호 RWIS 12410·33411·23402는 학습·임계값 선택·성능 진단에 사용하지 않았다. 실제 결빙 분류기를 처음 실행한 **개발용 잠정 평가**이며 공식 검증 점수가 아니다. [평가 규약](VALIDATION_PROTOCOL.md)의 하루 10분 시점 집계·완전한 144개 유효 짝·정의 불가능한 지표 `null` 규칙을 사용했다. 운영진 답변 전 일별 점수를 최종 공식 성능으로 표현하지 않는다.

## 데이터와 재현 방법

노면온도 값이 없는 행 때문에 유효 Ice 정답이 누락되지 않도록, `scripts/build_ice_features.py`는 노면상태를 별도 타깃으로 읽었다. 개발용 14개소 **483,805시각** 중 정의된 상태 **483,652시각**, Ice **239시각**, 미정의 **153시각**으로 [기존 EDA](EDA_REPORT.md)와 정확히 일치했다. 후방 60분 이내의 AWS·ASOS 기상만 입력으로 사용했고 대상 RWIS의 노면온도·노면상태·지연값은 특징에서 제외했다. `state_raw`와 미정의 정답은 비공개 출력에 추적하며, 10분 예측은 정답이 없는 시각에도 생성한다.

첫 모델은 결측 중앙값/결측 표시·표준화·클래스 가중 로지스틱 회귀(C=0.1) 한 종류다. 각 외부 LOSO 회차에서 나머지 13개 관측소를 학습하고, 그 내부 3개 관측소 분할의 OOF 점수로 **전체 10분 통합 F1 최대 임계값**을 정했다. 보류 지점의 정답은 임계값 선택에 사용하지 않았다. 클래스 가중 모델의 `model_score`는 보정된 결빙 확률이 아니다. 두 방식은 동일한 모델·분할·목표 시각을 쓰며, 가장 가까운 AWS만 쓰는 경우와 3개 후보 중 유효한 과거 AWS를 고르는 경우만 다르다.

| 개발용 10분 통합 보조지표 | 최근접 AWS | 가용 AWS 대체 |
| --- | ---: | ---: |
| 평가 가능한 시각 | 483,652 | 483,652 |
| TP / FP / FN | 164 / **96,743** / 75 | 21 / **955** / 218 |
| Precision | 0.00169 | 0.02152 |
| Recall | 0.68619 | 0.08787 |
| F1 | 0.00338 | 0.03457 |

가용 AWS 대체는 실제 Ice 239시각 중 AWS 기온 연결을 **134→214시각**으로 늘렸지만, 해당 분류 모델의 TP는 오히려 줄었다. 대체 모델의 TP 21건은 모두 12210 한 지점에서 나왔고 나머지 결빙 지점에서는 TP가 0이었다. 최근접 모델은 많은 Ice를 찾았지만 FP가 96,743건으로 운영 가능한 판정기가 아니다. **어느 모델도 최종 분류기로 채택하지 않았다.**

## 일별 지표 해석의 핵심 함정

동일한 3,308개 지점·날짜가 144개 유효 시각 조건을 충족했다. 그러나 F1이 정의되는 날짜는 최근접 모델 1,794개와 대체 모델 240개로 크게 다르다. 둘 다 무결빙·무경보인 날짜는 점수를 0 또는 1로 만들지 않고 `null`로 남겨서, 이 두 일별 평균을 그대로 비교하면 **분모가 달라진다**. 보조 비교로 두 모델에 공통인 **실제 Ice가 있는 지점·날짜 110개**만 보면 10분 F1의 날짜 동일가중 평균은 최근접 **0.04134**, 대체 **0.01037**이다. 반면 실제 무결빙이면서 경보가 있는 지점·날짜는 **1,684→130개**로 줄었다. 이는 공식 일별 평균을 대신하는 점수가 아니라 TP–FP 교환 관계를 드러내는 공통 분모 진단이다.

## 실패 원인과 다음 결정

실제 Ice 시각의 노면온도 중앙값은 −1.7°C이지만, 노면온도가 0°C 이하인 유효 **비결빙** 시각도 **141,024개**였다. 이 노면온도는 오직 사후 진단에 사용했고 분류 입력으로 넣지 않았다. 최근접 AWS의 15분 강수값은 Ice 239시각 중 134시각에만 있었고 그중 13시각에서만 강수가 양수였다. 짧은 강수 창과 현재 기온만으로 표면 수분·서리·재결빙을 충분히 구별하기 어렵다는 **자료 기반 가설**이다. Ice 215사건 중 198사건이 한 시각이라는 기존 EDA는 원시 정답을 자동 제외할 근거가 아니라, 전후 시각·센서 상태를 확인할 우선순위다.

다음 실험은 모델 종류를 무작정 늘리기보다 (1) 개발용 단일 시각 Ice의 전후 상태·기상 QC, (2) 입력 시점 이전의 1–3시간 강수·습도·이슬점·지면온도/운량의 정의와 가용성, (3) **학습 지점 안에서만** 지점 균형·실제 Ice 날짜 탐지·허용 오경보를 함께 고려하는 임계값 선택을 먼저 설계한다. 그 뒤 도로·지형 특징과 추정 노면온도 OOF의 추가 이득을 같은 LOSO에서 비교한다. 임계값을 현재 외부 OOF 결과에 맞춰 재조정하지 않는다.

재현 명령은 아래와 같다. 전체 로지스틱 실험은 내부 분할을 포함하므로 먼저 작은 실행을 한다. 작은 실행에서는 음성을 표본 추출해 원래 희귀도와 다르므로 점수는 성능 근거로 사용하지 않는다.

```powershell
python scripts/build_ice_features.py --limit-days 2
python scripts/build_ice_features.py
python scripts/baseline_ice_logistic.py --smoke
python scripts/baseline_ice_logistic.py
python scripts/build_aws_fallback_features.py --target ice
python scripts/baseline_ice_logistic.py --smoke --variant fallback
python scripts/baseline_ice_logistic.py --variant fallback
python scripts/compare_ice_variants.py
python scripts/diagnose_ice_baseline.py
```

10분 OOF 예측, 일별 점수, 임계값, 지점별 결과는 Git 제외 경로 `outputs/private/ice_logistic/`, `ice_fallback_logistic/`, `ice_variant_comparison/`, `ice_diagnostic/`에 있다. 보호 3개소 예측과 공식 제출 CSV는 아직 만들지 않았다.
