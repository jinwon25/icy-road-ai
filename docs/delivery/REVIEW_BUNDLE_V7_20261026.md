# v7 보고서·검토 안내 개편

v7은 10쪽 분석 보고서와 심사자 검토 안내를 추가하고 문서의 읽는 순서를 정리한 비공개 제출 검토 묶음이다. 온도 모델 v3와 결빙 판정 v2를 사용하며 기존 모델·자료·예측·CSV·지도·노트북·데모를 보존한다. 문서 개편을 성능 개선으로 해석하지 않는다.

[보고서 원고](ANALYSIS_REPORT.md) · [유사 대회 비교와 편집 기준](BENCHMARK_REVIEW_20261025.md) · [심사자 검토 안내](REVIEWER_GUIDE.md)

## 무엇이 달라졌는가

- 온도 개선, 결빙 기준선 미달, 새 4지역 평가를 하나의 보고서에 통합하였다.
- 표본·기간·단위·지표 분모와 채택 기준을 설명하고, 통계적 관찰과 원인 가설을 구별하였다.
- 보고서의 내부 버전명·자기평가 문구를 줄이고 서지정보·실제 적용 범위를 보완하였다.
- 노트북은 기존 코드 셀 5개를 그대로 둔 새 사본에서 현재 보고서 경로와 기온 기준선 수치 차이를 설명하였다. 이전 노트북도 보존한다.
- README는 현재 결과와 읽는 경로 중심으로 축약하고, 누적 이력은 과거 기록으로 분리하였다.
- 원고에서 PDF를 생성하여 두 문서의 문장을 일치시키고 핵심 수치를 기존 결과 JSON과 대조하였다.

## 구성과 실행

로컬 폴더는 `outputs/private/submission_candidate_20261026_v7/`이며 같은 상위 폴더에 ZIP과 검증 영수증을 둔다. 현재 보고서는 `reports/analysis_report_v7.pdf`이다. 이전 `reports/current/current_report.pdf`는 10월 24일의 8쪽 보고서로 보존되며, 폴더 이름과 달리 최신 보고서가 아니다. 묶음 README는 새 보고서를 첫 진입점으로 안내한다.

```powershell
python -m pip install -r requirements-notebook.txt
python scripts/review_submission_bundle.py
python scripts/review_submission_bundle.py --smoke --output local_review/smoke.json
```

모든 검사 출력은 `local_review/`에 생성한다. 이미 같은 파일이 있으면 새 이름을 사용한다. 예제 예측 144행과 노트북 실행은 포함 파일로 확인하며, 전체 연구 탐색에는 원 작업 공간의 비공개 입력이 추가로 필요하다.

## 검증 근거

보고서 생성 영수증은 `validation/v7_report_source.json`, 페이지별 시각 검수는 `validation/v7_report_visual.json`, 보존·실행 검사는 `validation/v7_delivery.json`이다. ZIP 영수증은 압축 구성원 전체를 manifest와 대조한 결과이며 폴더 내부 검증과 구별한다.

| 검사 | 확인한 결과 |
| --- | --- |
| 보고서 | 10쪽 전부 렌더 검수, 기존 집계의 핵심 수치 20개 자동 대조 |
| 기존 실행 자산 | 모델·자료·예측·지도·노트북·보고서 등 504파일의 v6 해시 일치 |
| 예제 추론 | 144행이 포함 기준 파일과 정확히 일치 |
| 노트북 | 기존·새 노트북 각각 실행 성공, 새 사본의 코드 셀 5개 동일 |
| 문서 | 저장소 Markdown 87개, 묶음 Markdown 96개 링크·GFM 검사 통과 |
| 코드 검사 | 388개·하위 검사 7개 통과. 동결 코드의 pandas 향후 변경 경고 1건 기록 |
| 기존 기록 | 보호 봉인 47+549개, 새 4지역 완료 평가와 v6 ZIP 보존 |

현재 PDF의 SHA-256은 `f8e17e0824c1b70baa7d3ad8d84062720c4f9827e6db41bc927646e252d51c28`이며 378,376바이트이다. PDF 생성 원고와 묶음 Markdown은 같은 문장이다. Git의 CRLF/LF 정규화에 따른 바이트 차이는 `validation/v7_manuscript_equivalence.json`에서 구별한다. 압축 파일의 최종 크기·SHA-256·전체 구성원 검사는 상위 폴더 `submission_candidate_20261026_v7.receipt.json`을 기준으로 한다.

첫 묶음 검증 후 기존 노트북의 과거 보고서 연결을 발견하였다. 초기 검증은 `validation/v7_delivery_before_notebook_refresh.json`으로 보존하고, 설명을 바꾼 새 노트북과 현재 PDF를 반영하여 최종 검사를 다시 수행하였다. 성능표·모델·예측을 수정한 작업은 아니다.

기존 사용자 미커밋 문서와 로그를 보존하며 묶음에는 Git 인덱스의 문서를 사용한다. 타 대회의 참고 PDF는 묶음·저장소에 포함하지 않는다. 원자료·모델·전체 예측·ZIP·인증정보는 GitHub 반영 대상에서 제외한다. AI 지원 기록은 유지하고 참가자의 직접 검토를 대신했다고 표현하지 않는다.
