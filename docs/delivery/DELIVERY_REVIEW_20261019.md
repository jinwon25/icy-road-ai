## 발견한 문제와 수정

기존 `notebooks/analysis_review.ipynb`는 `outputs/private`의 집계 파일을 읽고 기본 실행 중 원본 ZIP이 필요한 `audit_data.py`를 호출합니다. 10월 16일 ZIP에는 그 작업 공간과 원본이 없습니다. 노트북 파일의 존재만 확인하면 심사 환경의 실행 가능성을 놓치게 됩니다. 후보의 최소 추론용 `requirements.txt`에도 Jupyter 실행 의존성이 없었습니다.

새 [submission_review.ipynb](../../notebooks/submission_review.ipynb)는 압축 해제한 후보 내부의 학습 식별자·저장 모델·기상 예제·기존 개발 예측만 사용합니다. 실행 순서는 학습 범위 확인, 144행 추론, 여섯 방법·네 관측량 조건의 24개 지표 검산입니다. 재학습은 기본적으로 꺼져 있으며, 선택할 때도 별도 새 경로에서 같은 설정으로만 실행합니다. 과거 연구 노트북은 보존합니다.

[requirements-notebook.txt](../../requirements-notebook.txt)에 커널 실행 의존성을 고정했습니다. 기존 노트북 검사기는 사용자 `.ipython` 이력 DB에 쓰기를 시도해 이 환경에서 실패했으므로 [check_notebook.py](../../scripts/check_notebook.py)를 임시 프로필·연결 파일 사용으로 수정했습니다. 실패 로그를 보존하고 실제 Jupyter 커널에서 새 노트북의 코드 셀 5개를 모두 통과했습니다. 노트북 출력은 저장하지 않았습니다.

## 실행과 보존

새 로컬 후보는 `outputs/private/submission_candidate_20261019_v1.zip`입니다. 모델·데이터·연구 결과·데모·기존 보고서는 10월 16일 파일 해시와 비교해 보존합니다. 기존 ZIP과 실패 기록도 남겨 둡니다. 최종 묶음의 크기·전체 해시는 `outputs/private/delivery_review_20261019_v1/package_receipt.json`, 세부 감사는 같은 폴더의 `audit.json`에 기록합니다.

```powershell
python -m src.submission_archive --archive outputs/private/submission_candidate_20261019_v1.zip --output outputs/private/candidate_review_20261019
python -X utf8 scripts/check_notebook.py outputs/private/candidate_review_20261019/notebooks/submission_review.ipynb
```

원 연구 작업 공간에서 재생성하는 [review_delivery_20261019.py](../../scripts/review_delivery_20261019.py)의 순서는 `--stage prepare`, `--stage audit`, 문서 확인 후 `--stage package`입니다. 완료된 폴더·ZIP은 덮어쓰지 않습니다. 수집 스크립트는 [review_official_updates.py](../../scripts/review_official_updates.py)이며 날짜를 바꾸려면 새 출력 폴더와 직전 완료 스냅샷을 지정합니다. 기존 HWP 도구가 있는 연구 환경에서 사용합니다.
