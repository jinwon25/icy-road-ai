## 실행된 후속 입력 감사

`python scripts/audit_aws_fallback.py`는 비공개 `outputs/private/weather_features/features.parquet`에서 개발 RWIS의 **지점·시각·기존 AWS 기온 가용 여부**만 읽고, 원본 ZIP의 AWS 기온과 감사된 지점 좌표를 결합한다. 노면온도와 Ice 정답은 읽지 않는다. 사용한 AWS 값은 목표 시각보다 엄격히 이전이며 60분 이내다. 2일 작은 실행은 `--smoke`다. 지점별 연결률과 거리·관측 나이는 Git 제외 경로 `outputs/private/aws_fallback/`에 있다.

전체 483,777시각에서 가장 가까운 AWS의 마지막 유효 과거값은 340,521시각이며, 현행 특징의 최근 행 값 340,453시각보다 **68시각** 많다. 가까운 AWS가 유효하지 않을 때 2·3순위 AWS가 **93,732시각**을 추가로 연결한다. 여전히 **49,524시각**에는 세 후보 모두 60분 내 유효한 기온이 없다. 12209의 후보 거리는 4.45, 5.21, 17.96km다. 이는 시간 가용성의 상한 후보이며 실제 발표 지연은 확인되지 않았다. 특히 3순위 먼 관측소는 가용성 증가와 함께 공간 대표성 저하가 생길 수 있다.

다음 순서는 (1) 대체 입력으로 공정한 기상 기준 재실험, (2) 시설·DEM의 의미와 시간 적합성 점검, (3) 동일 LOSO에서 기상만/기상+정적 특징 비교다. 결빙 분류와 지도 등급은 공식 평가 정의 및 특징 품질 확인 뒤 개발 자료로 설계한다. 실험에서 악화된 지점도 평균에 숨기지 않고 모두 제시한다.

## 동일 분모의 대체 AWS 모델 비교 — 2026-09-23 실행

가용성 감사 뒤 상위 3개 AWS 중 기온이 있는 가장 가까운 지점의 **과거 60분 이내** 관측으로 기상 특징을 다시 만들었다. 선택한 지점의 기온·습도·풍속·15분 강수·이슬점과 거리·관측 나이를 함께 사용한다. 기존과 같은 Ridge α=100, 같은 14개 관측소 단위 LOSO, 같은 ASOS 유효 483,095시각으로 비교했다. 각 fold의 결측 대체·표준화는 학습 지점에서만 적합했다. 두 버전의 평가 지점·시각·정답·ASOS 기준 예측이 완전히 일치하는지 코드로 검사했다.

**반례:** 12209는 MAE 2.460→2.406°C로 나아졌으나 ASOS 보정 기준 2.262°C보다 여전히 나쁘다. 예측−관측 BIAS도 +2.084→+1.995°C로 큰 양의 편향이 남는다. 관측 노면온도 −2–2°C 구간에서는 23202의 MAE가 1.004→1.016°C로 악화됐다. 이 구간은 모델 입력이 아니라 평가용 사후 진단이며 Ice 분류 성능이 아니다. 연속된 10분 자료의 시간 의존성이 커서 행 수만으로 개선의 통계적 유의성을 주장하지 않는다.

결정: 대체 AWS를 **다음 기상 기준 후보**로 유지하되 최종 모델로 확정하지 않는다. 12209의 온난 편향과 23202의 0°C 부근 악화를 먼저 점검하고, 시설·DEM의 의미와 관측 시점 적합성을 확인한 뒤 같은 LOSO에서 도로·지형 특징의 추가 이득을 비교한다. 공식 보류 3개 지점은 계속 열지 않는다. 실행 코드는 scripts/build_aws_fallback_features.py, scripts/baseline_weather_ridge.py --variant fallback, scripts/compare_weather_variants.py이며 지점별 비공개 결과는 outputs/private/weather_fallback_comparison/에 있다. 단일 분석 노트북의 마지막 셀에서 결과를 확인·재실행할 수 있다.
