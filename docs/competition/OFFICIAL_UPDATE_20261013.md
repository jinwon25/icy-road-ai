## AI 활용과 외부 API의 적용 범위

[일반 Q&A618](https://aida.kisti.re.kr/competition/main/selectQna.do?bbsId=BBSMSTR_BBBBBBBBBBBB&nttId=618)은10월9일 운영진 답변이며 이번에 처음 상세 대조했습니다. 이번 새 FAQ와 구별합니다. 설계·개발에서 생성형 AI 지원을 받을 수 있고 활용 범위·주요 검토 과정을 제출해야 하며, 외부 API로 분석 또는 예측을 직접 수행하는 것은 원칙적으로 허용하지 않는다고 안내합니다. 문제별 제한도 별도로 확인하라고 명시합니다.

이 답변은 [문제별588 답변](https://aida.kisti.re.kr/competition/problem/PROB_000000000004604/detail/commuDetail.do?bbsId=BBSMSTR_000000000319&nttId=588)의 공개 공공 기상자료 학습 허용·출처/활용 근거 제출 조건과 함께 읽었습니다. **공개 관측자료 수집, AI의 코드 작성 지원, 외부 서비스에 분석·예측을 맡기는 실행은 서로 다른 역할**로 기록합니다. 평가 실행 중 원자료 API 조회가 어느 범위까지 허용되는지는 별도 확답을 확보하지 못했습니다. 이번 추론은 이미 보존한 캐시와 로컬 모델만 사용했습니다.

실제 `src/`의 네트워크 관련 구현은 KMA 원문 관측 수집용 transport에서 확인했습니다. 기존 데모·이번 후보 추론의 학습/예측 계산은 저장 모델의 로컬 `predict`·`predict_proba`입니다. 외부 LLM 예측 서비스로 관측 행을 보내는 추론 경로를 추가하지 않았습니다. 이 코드 검토와 아래 실행 검증을 전체 코드의 모든 가능한 실행 경로나 OS 수준 네트워크 격리 보증으로 표현하지 않습니다.

## 이번에 실제 진행한 후속 작업

`src/offline_runtime.py`와 `verify_offline_inference_20261013.py`로 Python DNS·TCP 연결·UDP 송신 시도를 차단한 상태에서 캐시 읽기·모델 역직렬화·실제 추론을 수행했습니다. 호출 인자·주소·인증값은 기록하지 않고 인터페이스별 시도만 셉니다. 오류가 발생해도 원래 함수가 복구되며, 호출 오류를 내부에서 잡아도 시도 기록이 남는 경계를 테스트했습니다.

대상은 이미 개발에 사용한12207의2024-12-15 KST 하루144행입니다. 같은 공간 그룹을 학습에서 제외한 기상12·MSE300·MAE300 세 온도 모델과 미채택 CatBoost를 재실행했습니다. 온도 세 성분·고정 평균·경험적 하한/상한·분류 점수 **1,008개 값이 저장된 결과와 허용오차1e-10 이내로 일치**했습니다. 분류는 기존 교차 추정 온도를 입력으로 유지하며 새 평균 온도로 바꾼 모델처럼 발표하지 않습니다.

추론 중 확인한 네트워크 시도0건·외부 예측 API 호출0건·새 학습0건입니다. 실제 목표 온도·상태 정답을 읽어 채점하지 않았고 보호·개봉8/4/2·다음 겨울 평가 정답도 사용하지 않았습니다. 기존47개·외부549개 고정 파일과 세 평가 봉인을 유지했습니다. 이는 실행 재현성 확인으로, 새 독립 성능이나 후보 승격 근거가 아닙니다.

`build_offline_review_bundle_20261013.py`는 모델4개·하루 입력2개·대조 예측·실행 스크립트·고정 환경 버전·설명을11개 소스 파일, 약1.3MB의 비공개 묶음으로 준비했습니다. 원본ZIP·실제 상태/노면온도 정답·인증키·계정 정보는 포함하지 않습니다. 별도 Python 프로세스에서 로컬 사본을 다시 실행해144행의 최종 네 출력576개가 일치했습니다. 원래 소스·큰 캐시 경로에 기대지 않고 패키지 안의 입력·모델만 읽습니다. 참가 권한 내 검토용이며 최종 제출·외부 전송·공개는 수행하지 않았습니다.
